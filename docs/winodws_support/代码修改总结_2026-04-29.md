### 2. tui_gateway/transport.py

#### 冲突原因

上游在提交 `1e326c68`（`fix(tui-gateway): harden stdio transport against half-closed pipes + SIGTERM races`）中对 `StdioTransport.write()` 进行了大幅重构：

- 新增 `_PEER_GONE_ERRNOS` 常量，细分 `OSError` errno
- 新增 `_DISABLE_FLUSH` 开关，防止半关闭管道导致 flush 挂起
- 将 `BrokenPipeError` 拆分为 `BrokenPipeError` / `ValueError("closed file")` / `OSError` 三类处理
- write 和 flush 分别独立处理异常

我们在 04-26 的修改绕过 `TextIOWrapper` 直接写 UTF-8 字节到底层 `buffer`，以解决 CJK Windows 上 GBK 编码误转问题。两处修改在同一函数体内产生冲突。

#### 解决方案

将上游的健壮错误处理框架与我们的 Windows UTF-8 buffer bypass 合并：

**修改位置：** `tui_gateway/transport.py`（`StdioTransport.write()` 方法）

```python
# 最终结果（两处修改合并）
with self._lock:
    stream = self._stream_getter()
    # On CJK Windows the TextIOWrapper may use GBK; bypass it by
    # writing UTF-8 bytes directly to the underlying buffer so
    # Chinese characters are never mis-encoded.
    buf = getattr(stream, "buffer", None)
    try:
        if buf is not None:
            buf.write(line.encode("utf-8"))
        else:
            stream.write(line)
    except BrokenPipeError:
        return False
    except ValueError as e:
        if isinstance(e, UnicodeEncodeError) or "closed file" not in str(e):
            raise
        return False
    except OSError as e:
        if e.errno not in _PEER_GONE_ERRNOS:
            raise
        logger.debug("StdioTransport write peer gone: %s", e)
        return False

    if not _DISABLE_FLUSH:
        flush_target = buf if buf is not None else stream
        try:
            flush_target.flush()
        except BrokenPipeError:
            return False
        except ValueError as e:
            if isinstance(e, UnicodeEncodeError) or "closed file" not in str(e):
                raise
            return False
        except OSError as e:
            if e.errno not in _PEER_GONE_ERRNOS:
                raise
            logger.debug("StdioTransport flush peer gone: %s", e)
            return False

return True
```

**策略：** flush 时同样优先使用底层 `buf`（`flush_target = buf if buf is not None else stream`），确保 Windows UTF-8 bypass 在 flush 路径上也生效。

## 构建修复：@nous-research/ui 升级至 0.10.0

#### 问题

合并后 `npm run build` 报 112 个 TypeScript 错误，原因是 `@nous-research/ui` 的 lock 文件指向了过渡期破坏性版本 0.4.0，该版本删除了大量 API：

- **缺失导出**：`ListItem`、`Spinner`、`Select`、`SelectOption`、`Switch`、`FilterGroup`、`Segmented`、`Tabs`、`TabsList`、`TabsTrigger`
- **Button props 移除**：`ghost`、`size`、`destructive`、`outlined`
- **Badge props 移除**：`tone`

#### 根因

0.4.0 是上游 UI 库的一个中间过渡版本，破坏了向后兼容性。最新稳定版 **0.10.0** 已将上述所有 API 全部恢复。

#### 解决方案

在 `web/` 目录执行 `npm install`，`package-lock.json` 被重新解析并锁定至最新稳定版 **0.10.0**。无需修改任何 TypeScript 源码，构建恢复正常（`✓ built in 8.50s`，0 个 TS 错误）。
