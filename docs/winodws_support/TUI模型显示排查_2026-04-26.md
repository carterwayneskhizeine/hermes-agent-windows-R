# TUI 模型显示错误排查记录：恢复会话时显示 claude-sonnet-4

> 日期：2026-04-26
> 现象：Web Dashboard `/chat?resume=<id>` 恢复会话后，TUI 右上角模型徽章始终显示 `claude-sonnet-4`，与实际使用的模型不符
> 影响组件：`tui_gateway/server.py`、Web ChatSidebar、Ink TUI 状态栏

---

## 问题现象

在 Web Dashboard 中通过 URL `http://127.0.0.1:<port>/chat?resume=<session_id>` 恢复会话时，TUI 右上角的模型名称始终切换为 `claude-sonnet-4`，即使配置文件中指定的模型完全不同（如 `glm-4.7`、`MiniMax-M2.7`、`deepseek-chat`）。

实际 inference 请求使用的是正确模型，仅显示标签错误。

---

## 架构背景

Web Dashboard 的 chat 页面涉及三个独立进程：

```
┌─────────────────────────────────────────────────────┐
│  浏览器 (ChatPage.tsx)                               │
│    ├── xterm.js 终端 ← WebSocket /api/pty           │
│    └── ChatSidebar  ← WebSocket /api/ws + /api/events│
└──────────────┬──────────────────────────────────────┘
               │
┌──────────────▼──────────────────────────────────────┐
│  Python Web Server (FastAPI/uvicorn)                 │
│    ├── /api/pty → PtyBridge → Node.js TUI 进程       │
│    ├── /api/ws  → tui_gateway.ws.handle_ws (进程内)  │
│    └── /api/events ← /api/pub (事件广播)             │
└──────────────┬──────────────────────────────────────┘
               │ PTY (ConPTY on Windows)
┌──────────────▼──────────────────────────────────────┐
│  Node.js TUI (ui-tui/dist/entry.js)                  │
│    └── spawn: python -m tui_gateway.entry             │
│        └── tui_gateway.server (独立 gateway 实例)     │
└─────────────────────────────────────────────────────┘
```

关键点：

1. **Web Server 进程**通过 `/api/ws` 直接加载 `tui_gateway.server`，处理 ChatSidebar 的 JSON-RPC 请求（创建 ephemeral session）。
2. **PTY 子进程**内的 TUI 通过 stdio 与另一个独立的 `tui_gateway.server` 实例通信。
3. 两个 gateway 实例各自独立执行 `_resolve_model()`，但共享同一个 `HERMES_HOME` 环境变量和配置文件。
4. **模型显示来源**：ChatSidebar 的模型徽章来自其 ephemeral session 的 `session.info` 事件；Ink TUI 的状态栏来自 PTY gateway 的 `session.info` 事件。

---

## 根因分析

### 直接原因

`tui_gateway/server.py` 中的 `_resolve_model()` 函数在无法从配置中获取模型名称时，返回硬编码的 fallback 值：

```python
# tui_gateway/server.py:565-576
def _resolve_model() -> str:
    env = (
        os.environ.get("HERMES_MODEL", "")
        or os.environ.get("HERMES_INFERENCE_MODEL", "")
    ).strip()
    if env:
        return env
    m = _load_cfg().get("model", "")
    if isinstance(m, dict):
        return str(m.get("default", "") or "").strip()
    if isinstance(m, str) and m:
        return m.strip()
    return "anthropic/claude-sonnet-4"  # ← 硬编码 fallback
```

当 `config.yaml` 中**没有 `model` 部分**或 `model` 部分为空时：

```yaml
# 场景 A：完全没有 model 配置
providers: {}

# 场景 B：model 存在但没有 default 键
model:
  provider: deepseek
  base_url: https://api.deepseek.com/
```

执行路径分析：

| 步骤 | 场景 A | 场景 B |
|------|--------|--------|
| `m = _load_cfg().get("model", "")` | `""` (空字符串) | `{"provider":"deepseek","base_url":"..."}` (dict) |
| `isinstance(m, dict)` | `False` | `True` |
| `m.get("default", "")` | — | `""` (空字符串) |
| `str("" or "").strip()` | — | `""` |
| 最终返回值 | **`"anthropic/claude-sonnet-4"`** | **`""` (空字符串)** |

场景 A 直接命中硬编码 fallback。场景 B 返回空字符串，由上游 `_session_info()` → `getattr(agent, "model", "")` 处理。

### 数据库证据

`turing` profile 的 `state.db` 中最近的 session 记录：

```
id=20260426_132134_...  model='anthropic/claude-sonnet-4'  ← 硬编码 fallback
id=mofbh3lqo5wqm4...   model='MiniMax-M2.7'
id=20260425_122529_...  model='MiniMax-M2.7'
```

最新的 session 记录确认 `model='anthropic/claude-sonnet-4'` 来自硬编码 fallback，而非用户配置。

### 加剧因素

`_load_cfg()` 的静默异常处理使问题难以发现：

```python
# tui_gateway/server.py:447-468
def _load_cfg() -> dict:
    global _cfg_cache, _cfg_mtime
    try:
        import yaml
        # ... 加载配置 ...
        return data
    except Exception:   # ← 吞掉所有异常
        pass
    return {}           # ← 返回空字典
```

如果 `pyyaml` 未安装（例如 gateway 子进程使用了错误的 Python 解释器），配置加载会静默失败，返回空字典，导致 `_resolve_model()` 走到硬编码 fallback。

### 模型显示的数据流

```
session.resume / session.create
  └→ _make_agent(sid, key, session_id=...)
       ├→ model, provider = _resolve_startup_runtime()
       │    └→ model = _resolve_model()  ← 这里返回 "anthropic/claude-sonnet-4"
       └→ AIAgent(model=model, ...)
            └→ self.model = model

_init_session(sid, key, agent, ...)
  └→ _emit("session.info", sid, _session_info(agent))
       └→ info["model"] = getattr(agent, "model", "")
            └→ WebSocket → 前端显示
```

**关键**：恢复 session 时不会从数据库读取旧 model，而是用 `_resolve_model()` 重新解析当前配置。如果配置为空，则使用 fallback。

## 修复方法

### 即时修复

在 `config.yaml` 中确保 `model.default` 有值：

```yaml
model:
  default: deepseek-chat   # ← 必须设置，否则 fallback 到硬编码值
  provider: deepseek
```

### 验证修复

```bash
# 1. 确认 HERMES_HOME 指向正确的 profile
export HERMES_HOME="C:\Users\<user>\.hermes\profiles\<profile>"

# 2. 激活 venv（确保 pyyaml 可用）
.\venv\Scripts\Activate.ps1

# 3. 验证 _resolve_model() 返回正确值
python -c "
import os
os.environ['HERMES_HOME'] = '$env:HERMES_HOME'
from tui_gateway.server import _resolve_model
print(_resolve_model())
"
# 期望输出：你在 config.yaml 中设置的 model.default 值

# 4. 启动 dashboard
python -m hermes_cli.main dashboard --no-open --tui --port 9120
```

## 建议改进

### 1. 为 `_resolve_model()` 添加 fallback 警告日志

```python
def _resolve_model() -> str:
    # ... existing logic ...
    fallback = "anthropic/claude-sonnet-4"
    logger.warning(
        "No model configured (no HERMES_MODEL env var, "
        "no model.default in %s/config.yaml). "
        "Falling back to hardcoded default: %s",
        _hermes_home, fallback,
    )
    return fallback
```

### 2. 改进 `_load_cfg()` 的异常处理

```python
def _load_cfg() -> dict:
    # ... existing logic ...
    except Exception as e:
        logger.warning("Failed to load config from %s/config.yaml: %s", _hermes_home, e)
    return {}
```

### 3. 考虑让 fallback 模型可配置

在 `hermes_constants.py` 或 `config.yaml` 中定义默认模型，避免硬编码特定供应商的模型名称。
