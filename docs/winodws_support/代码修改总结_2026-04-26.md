## 详细代码变更

### 1. tools/environments/base.py — 终端输出捕获（关键修复）

#### 问题

终端工具（terminal）执行命令后输出始终为空，`exit_code=0` 但 `output=""`。复杂命令如 `ls -la` 超时 180 秒。

#### 根因

`select.select([fd], [], [], 0.1)` 在 Windows 上只能用于 socket，对 pipe fd 会抛出 `OSError: [WinError 10093]`。drain 线程中的 `except OSError: break` 捕获后立即退出线程，导致所有输出丢失。

#### 修改

**文件位置：** `tools/environments/base.py`

新增平台检测常量：
```python
import platform
_IS_WINDOWS = platform.system() == "Windows"
```

将单一 `_drain()` 拆分为平台特定实现：

**POSIX 版（不变）：**
```python
def _drain_posix():
    while True:
        readable, _, _ = select.select([fd], [], [], 0.1)
        if not readable:
            if proc.poll() is not None:
                ...
                break
            continue
        chunk = os.read(fd, 4096)
        ...
```

**Windows 版（新增）：**
```python
def _drain_windows():
    buf = proc.stdout.buffer if hasattr(proc.stdout, "buffer") else proc.stdout
    try:
        while True:
            try:
                chunk = buf.read1(4096)
            except (ValueError, OSError):
                break
            if not chunk:
                break
            output_chunks.append(decoder.decode(chunk))
    finally:
        try:
            tail = decoder.decode(b"", final=True)
            if tail:
                output_chunks.append(tail)
        except Exception:
            pass

_drain = _drain_windows if _IS_WINDOWS else _drain_posix
```

**原理：** `proc.stdout.buffer.read1(4096)` 是阻塞读取，不依赖 `select`，在 Windows 管道上正常工作。进程退出后 buffer 关闭触发 `ValueError`，自然退出 drain 循环。

### 2. tui_gateway/entry.py — stdin UTF-8 重配置

#### 问题

TUI chat 页面刷新后，用户输入的中文消息变成乱码（"你好" → "浣犲ソ"），AI 回复正常。

#### 根因

`entry.py` 中对 `_real_stdout` 和 `sys.stderr` 做了 `reconfigure(encoding="utf-8")`，但遗漏了 `sys.stdin`。Node TUI 通过 JSON-RPC 发送 UTF-8 字节 → Python stdin 使用系统默认 GBK (cp936) 解码 → 产生乱码 → 被持久化到 SQLite 会话数据库。

#### 修改

**文件位置：** `tui_gateway/entry.py:117`

```python
# 修改前
for _s in (_real_stdout, sys.stderr):
    ...

# 修改后
for _s in (_real_stdout, sys.stderr, sys.stdin):
    if hasattr(_s, "reconfigure"):
        try:
            _s.reconfigure(encoding="utf-8", errors="replace")
        except Exception:
            pass
```

#### 补充：slash_worker.py 同步修复

**文件位置：** `tui_gateway/slash_worker.py:58-64`

slash worker 是持久化的 slash 命令子进程，同样通过 stdin 读取 JSON 命令，需要相同的编码保护：

```python
if sys.platform == "win32":
    for _s in (sys.stdin, sys.stdout, sys.stderr):
        if hasattr(_s, "reconfigure"):
            try:
                _s.reconfigure(encoding="utf-8", errors="replace")
            except Exception:
                pass
```

### 3. tui_gateway/transport.py — StdioTransport 绕过 TextIOWrapper

#### 问题

即使 `reconfigure` 了 stdout，Rich 等库可能在 stdout 上层叠加新的 TextIOWrapper，仍然使用 GBK 编码。

#### 修改

**文件位置：** `tui_gateway/transport.py:85-91`

```python
def write(self, obj: dict) -> bool:
    line = json.dumps(obj, ensure_ascii=False) + "\n"
    try:
        with self._lock:
            stream = self._stream_getter()
            # Bypass TextIOWrapper encoding (GBK on CJK Windows) by
            # writing UTF-8 bytes directly to the underlying buffer.
            buf = getattr(stream, "buffer", None)
            if buf is not None:
                buf.write(line.encode("utf-8"))
                buf.flush()
            else:
                stream.write(line)
                stream.flush()
        return True
    except BrokenPipeError:
        return False
```

### 4. subprocess 编码批量修复（146 处 / 41 文件）

#### 问题

Gateway 启动时崩溃：
```
[gateway-crash] UnicodeDecodeError: 'gbk' codec can't decode byte 0xa1 in position 0: illegal multibyte sequence
```

#### 根因

Python `subprocess.run(text=True)` 在中文 Windows 上默认使用系统代码页 GBK (cp936) 解码输出。当 git 输出包含非 GBK 字符（如 commit message 中的 Unicode 符号 ⚕ ✓ →）时解码失败。

#### 修改

所有 `subprocess.run/call(..., text=True)` 调用添加 `encoding="utf-8", errors="replace"`：

**典型修改（hermes_cli/banner.py）：**
```python
# 修改前
subprocess.run(["git", "rev-parse", ...], text=True, capture_output=True)

# 修改后
subprocess.run(["git", "rev-parse", ...], text=True, capture_output=True,
               encoding="utf-8", errors="replace")
```

**涉及的关键文件：**
- `hermes_cli/banner.py` — 4 处 git 命令
- `hermes_cli/main.py` — npm 子进程
- `hermes_cli/gateway.py` — 进程管理

### 7. hermes_cli/pty_bridge.py — ConPTY Windows 后端

#### 新增 Windows PTY 支持

使用 `pywinpty` 库实现 ConPTY（Windows 10+）伪终端，使 dashboard chat tab 可以嵌入完整 TUI 体验。

**平台检测：**
```python
if sys.platform == "win32":
    try:
        from winpty.ptyprocess import PtyProcess as _WinPtyProcess
        _PTY_BACKEND = "win"
    except ImportError:
        _WinPtyProcess = None
```

**Windows 读取：**
```python
def _read_win(self, timeout: float) -> Optional[bytes]:
    proc = self._proc
    try:
        old_timeout = proc.fileobj.gettimeout()
    except Exception:
        old_timeout = None
    try:
        proc.fileobj.settimeout(timeout)
        try:
            text = proc.read(65536)
        except _socket.timeout:
            return b""
        except EOFError:
            return None
        except OSError:
            return None
    finally:
        try:
            proc.fileobj.settimeout(old_timeout)
        except OSError:
            pass
    if not text:
        return b""
    return text.encode("utf-8")
```

if hasattr(signal, "SIGPIPE"):

    signal.signal(signal.SIGHUP, _log_signal)

### 9. tui_gateway/server.py + ChatSidebar.tsx — ephemeral session 修复

#### 问题

每次打开 Dashboard Chat 页面，侧边栏（`ChatSidebar`）连接到 dashboard 自己的 gateway（`/api/ws`）并调用 `session.create`，该 RPC 会通过 `db.create_session()` 写入一条数据库记录（`source="tui"`）。侧边栏卸载时只关闭了 WebSocket，没有调用 `session.close`，也没有清理数据库条目。导致 Sessions 页面每次访问 Chat 都多出一个空的「无标题会话」。

#### 修改

**tui_gateway/server.py — `session.create`（~L1485）：**

```python
# 新增 ephemeral 参数
ephemeral = bool(params.get("ephemeral"))

# 存入 in-memory session dict
_sessions[sid] = {
    ...
    "ephemeral": ephemeral,
    ...
}

# _build 线程中跳过 DB 写入
db = _get_db()
if db is not None and not ephemeral:
    db.create_session(key, source="tui", model=_resolve_model())
```

**tui_gateway/server.py — `session.close`（~L1833）：**

```python
# 关闭时对 ephemeral session 删除 DB 条目（安全网）
if session.get("ephemeral"):
    try:
        db = _get_db()
        if db is not None:
            db.delete_session(session["session_key"])
    except Exception:
        pass
```

**web/src/components/ChatSidebar.tsx（~L114-140）：**

```typescript
// 创建时传 ephemeral: true，不写数据库
gw.request<{ session_id: string }>("session.create", { ephemeral: true })

// 卸载时调 session.close 清理内存 session
if (sidecarSid) {
  gw.request("session.close", { session_id: sidecarSid }).catch(() => {});
}
gw.close();
```

## 修改总结

### 问题背景

在中文 Windows（系统代码页 GBK/cp936）环境下，Hermes 存在三大核心问题：

1. **Gateway 启动崩溃**：`subprocess.run(text=True)` 使用 GBK 解码 git 输出，遇到非 GBK 字符直接崩溃
2. **终端工具输出为空**：`select.select()` 在 Windows 管道上不可用，drain 线程立即退出
3. **TUI 中文输入乱码**：stdin 未重配置为 UTF-8，用户输入的中文被 GBK 错误解码后持久化

### 解决方案

1. **编码修复（146 处）**：全局搜索 `subprocess.*text=True` 无 `encoding=` 的调用，批量添加 `encoding="utf-8", errors="replace"`
2. **平台特定 drain**：Windows 使用 `proc.stdout.buffer.read1()` 替代 `select.select()`，彻底解决管道读取问题
3. **stdin 重配置**：`entry.py` 和 `slash_worker.py` 中 stdin/stdout/stderr 全部 reconfigure 为 UTF-8
4. **Transport 层绕过**：`StdioTransport.write()` 直接写 UTF-8 字节到底层 buffer，绕过 TextIOWrapper 编码
5. **ConPTY 支持**：使用 pywinpty 实现 Windows 伪终端后端
6. **Ephemeral session**：侧边栏 `session.create` 传 `ephemeral: true` 跳过 DB 写入，卸载时调 `session.close` 清理，避免 Sessions 页出现空会话
